# 从0开始的肥鱼大冒险（cortico-world-fun）

给 Coo（Coopanion）桌宠**二十处真能去逛的地方**：游乐场、海洋馆、庙会、漫展、电影院、动物园、公园、电玩城、KTV、博物馆、猫咖、爬山、**咖啡店、奶茶店、餐厅**、图书馆、夜市、澡堂、旧货市场、江边。

她一直「有地方可去，但没有真的去成」：发动态、刷视频、逛客厅都是零碎的，没有一趟**有头有尾**的出门。这个 World 补的就是这一趟：

- `fun_places` 看今天哪几处开着、人多不多（按开放时段和拥挤度排，不是随机给）；
- `fun_go` 进门，回执是进门那一下看到的样子和这一处能逛什么；
- `fun_wander` 一处一处地逛：过山车、鲸豚湾、捞金鱼、同人展台；顺手能买纪念品、拍张照；
- `fun_home` 回家，回执把这一趟收成一句话，**交给她 `feast_life_play` 记进自己的日程**，并告诉生图该填哪个场景名；
- `fun_shelf` 纪念品架：这些趟攒下来的东西按地方归着，写清哪件在哪儿哪天拿到的、还差什么没逛。

二十处场所、每处 5–8 个可逛的项目、纪念品、拍照点和随机小事件都是**内置**的，装完就能用，不依赖任何别的扩展。

## 家（第七个面板）

「世界 → 从0开始的肥鱼大冒险 → 家」是打开这个世界的第一屏：一张 2D 房间，她此刻在家做什么（发呆 / 读书 / 刷视频 / 打牌 / 打游戏 / 画画 / 做饭 / 看窗外 / 睡觉 / 聊天），点一下换个姿势；「布置房间」里能换房间背景和每个姿势的图，还能写一句房间备注。

- **没图也能用**：默认是一间纯 CSS 的纸色房间（墙、窗、沙发、地毯），缺图只是少一张画，不会白屏。
- **不是记录**：这里显示的是房间里的样子，不是她真的做过这件事；面板不写生活记录、不推进任何行程。
- **出门时只读**：显示「出门中 · 某地（逛了 1/3）」，在房间里换姿势不会影响正在走的行程。
- 素材规格、命名与十张贴图的对齐坐标见 [素材单](<E:/deep seek/素材单-鱼的家2D房间/素材单.md>)。

## 故事工坊预览

在「世界 → 从0开始的肥鱼大冒险 → 出游」打开文字版「鱼的家」。0.3.3 随版本内置四篇故事：《折潮港的第七封回信·简编版》《雨停前的小小清单》《桥底下的回声》《被换掉的说明牌》；前两篇是双人故事，后两篇是单人 v1 故事（江边、博物馆）。点「编写故事」也能创作，或在「故事工坊」导入自己的 v1/v2 作品。选择已保存作品明确出发，回家后回看实际经历；关窗重开可按已保存进度继续。原样章入口与样章专用场所已移除。

自主游玩需要当前 Persona 提供 World Cognition。缺少该接口时仍可完整手动游玩。自定义作品可在「地点册」建场所，再在「故事工坊」关联该场所并启用故事。

「鱼自己游玩」的额度在设置里改：`worlds.fun.funAutoSteps`（每段最多几步，默认 20，最多 200）和 `funAutoCalls`（每段最多几次「鱼自己决定」，默认 6，最多 120；每次都是一次真实模型请求）。用满后这一段停下，面板会说清是步数、决定次数还是同一步两次重试用完：可以点「再来一段（鱼自己玩）」，把这一段的步数与决定次数归零、段号加一（一趟最多三段，必须你亲手点，不自动续），也可以「我替她选」——鱼在这一步确实没法自己决定时才开放，会先问一次确认，回执和回忆里都记为 `substituted`，不会假装是鱼的决定。分支与续作保留已花额度，所以从一份用完额度的回忆里再开一段，仍然要靠「再来一段」或手动选。

自由模式（场景包）的回合说完后也一样：输入框收起，可以点「再来一段」把这一段的回合重新计（一趟最多三段，要你亲手点），或者收起进回忆。段号与本段起点写进存档，重启后仍在；`funStoryFreeTurns` 现在表示「每段多少回合」。

出游页默认是**对话式**：整页高度固定，标题、场景条、当前这一步（事件与选项）和底部状态都钉住，只有中间的发生记录自己滚；更早的片段与选择各折成一行，点开才展开。刷新或保存后回到原来的阅读位置，有新一步时自动滚到最新。顶栏的「沉浸」可切到**一屏一幕**：只有一张大图、这一回合的正文和这一步的选项，历史收进「回看」抽屉；两种读法共用同一份状态，切回来不会丢进度。

## F3–F5（0.3.2）

故事工坊支持 v1 与严格的 v2 格式。v2 包含作者、作品版本、类型、无剧透简介、参与方式、能力要求以及可选分钟数；未填时长显示未知。作者表单支持选地点、起始区域、两个选项及后续、预览、隔离试玩后保存；高级 JSON 入口保留。试玩只在临时状态重放，不保存正式行程、回忆或解锁。

v2 可在高级 JSON 中附加 `references`（最多 24 条）。每条使用 `{area, afterNode, afterChoice?, audience, text}`：`audience` 为 `player`、`fish` 或 `dm`，必须匹配当前区域、实际触发过的 `afterNode`，可另要求实际选过该节点的 `afterChoice`；每次最多给对应角色 6 条纯文本。玩家面板只显示 player 资料，鱼与主持分别在内部请求投影中获得各自资料；未来节点、未选线索和其他角色资料不随普通响应返回。为防模型复述私有资料，带私有资料的主持提议显示固定待确认说明，鱼选择记录使用固定公开理由。公共只读工具仍只回公开元数据与实际经历，不返回任何私有资料。v1 不接受这些新字段，旧版本内容摘要不变。

公开只读工具为 `fun_story_places`、`fun_story_candidates`、`fun_story_detail`、`fun_story_current`、`fun_story_recap`、`fun_story_schedule`。它们不开始故事、不推进事件、不写入每一天或长期记忆；作者管理工具 `fun_story` 仍标为写权限。指定作品从故事面板明确出发，并重新验证作品版本和条件；普通 `fun_go` 不等于启动指定故事。

v2 节点可声明 owner/fish/joint，鱼自主只控制 fish，owner 必须通过用户按钮提交；共同选择按作者声明处理分歧，等待与超时不会变成同意。单人旧故事保持兼容；0.3.3 已移除双人预设故事，不影响作者自己编写双人作品。

可选文本主持 `funStoryDM` 默认关闭。去「出游 → 设置」填写接口地址、API Key 和模型名；地址与 Key 都是密码输入，失焦和保存后只显示掩码与「已保存 / 未设置」。地址与 Key 两项留空使用宿主 `cognition.request`；都填写则由本插件直连 OpenAI 兼容 `POST /chat/completions`（填写 `https://服务地址/v1` 或完整 `/chat/completions` 路径，不含 URL 凭据、查询或片段）。模型名按你的服务商填，例如 `deepseek-chat`、`qwen-plus`、`gpt-4o-mini`；留空则不发送 `model` 字段，由接口使用它自己的默认模型，宿主配置不受影响。仅 Windows 使用 DPAPI CurrentUser 加密地址和密钥，密文单独保存在 `<dataDir>/fun/story-secrets.json`；密钥由 Windows 用户环境保护，不与密文同文件。其他平台禁用自定义凭据保存，仍可使用宿主模型。明文不进入 config/state、日志、工具回执、describe、提示词或作品导出。密钥只发送至用户填写的接口，不发给宿主或其他插件；换机器或重装后需重填。「清除密钥」立即撤销旧请求和提议，随后删除密文；之后回到宿主模型，宿主不可用则明确提示，手动游玩始终可用。

主持严格只提议当前合法选项，须由当前行动者明确提交。每趟最多 6 次、每步最多 2 次（含重试、失败、取消）；请求前保存预算，重启后保留。已报告的实际 token 单独累计，未知用量不估算。接口等待最多 20 秒，401/403、429、超时与格式错误均给出固定安全提示；不回显地址、密钥或响应正文。取消或超时不会应用迟到提议，直连会中止本地 HTTP；宿主或上游已接收的请求仍可能计费。本地验证仅使用模拟 HTTP，不代表已验证任何真实模型服务。

故事动作保存包含内容与资源版本的检查点。回忆中可从可继续检查点创建新 runId，并保留来源和已消耗预算；分支不会覆盖源回忆，不写入正史探索、收藏、心愿或后续资格。事实摘要可复制，复制不会写入生活或长期记忆。

「回忆」页每张卡有「移到回收站」：删掉的行程从回忆与纪念册移除，但会留在页面底部的「回收站（N）」里，可以恢复或彻底删除，也能一键清空。回收站最多 30 条、重启后仍在；纪念品架是独立收藏账本，删回忆不会拿走已经带回家的东西；正史完成记录也不会因此回退。

剧情图片生成 `funStoryImages` 是独立的默认关闭开关。打开后在故事面板的设置区填写**一个来源**，明确点击「生成/委派当前场景图片」；回家时可取得委派回执。文字故事不等待图片，关闭时不发任何图片请求，只使用预制或显式导入插画。

**自定义工作流（可选，仅直连本机 ComfyUI 时生效）**：在「出游 → 设置 → 剧情图片生成」的「自定义工作流」里贴 ComfyUI 的 **API 格式** JSON（界面里「Save (API Format)」导出），把正向提示词那段文字换成 `{{prompt}}`（必填）；想固定种子写 `{{seed}}`，不写则每次自动随机，避免 ComfyUI 按提示词缓存出同一张图。它会整体替换内置的 512×512 图：模型、尺寸、步数、LoRA 全由你的工作流决定，因此**不再查询 `/object_info/CheckpointLoaderSimple`**，出图取 `outputs` 里第一个带回 `images` 的节点（SaveImage 节点 ID 随意）。限制：≤ 32 KB、≤ 200 个节点、节点只接受 `class_type` / `inputs` / `_meta`；不合法时保存会被拒绝并保留原有来源。设置与来源一起存在 `fun/story-images/settings.json`，不写 World 状态或普通配置。

直连协议为 ComfyUI 的 `GET /object_info/CheckpointLoaderSimple` → `POST /prompt` → `GET /history/{prompt_id}` → `GET /view`。不访问宿主工具 HTTP 路由、不自动调用其他 World、不跟随重定向或外部图片 URL，因此不是越过 World 工具边界的内部 HTTP 旁路。取消/变更配置/继续故事会停止本地等待并拒绝迟到结果；ComfyUI 已排队任务可能仍执行。生成、轮询和下载均不占用故事动作队列。

本轮只在隔离副本验证，不安装或发布 0.3.3；真实 Coo、真实模型服务与真实 ComfyUI 仍需后续另行实机验收。

### Configuration and authoring (0.3.3)

In Fish Story World settings, the API URL and Key are password fields and the model name is a plain optional field. Blank URL and Key use host cognition; setting both calls OpenAI-compatible `POST /chat/completions` directly, and a blank model sends no `model` field so the endpoint applies its own default. Windows DPAPI CurrentUser encrypts URL and Key in `fun/story-secrets.json`; other platforms fail closed for custom credentials. No plaintext reaches ordinary configuration, state, logs, receipts or exports. Re-enter after changing machines or reinstalling. Clear revokes captured requests immediately and returns to host cognition. Limits remain 6 calls per trip / 2 per step, including failures and cancellations; timeout and upstream errors never echo credentials.

Image generation is off by default. A blank source returns executable `imggen_draw` scene/outfits/prompt for the main conversation; Fish Image Studio is required. Without a verified discovery API its installation remains explicitly unknown, and the main conversation must report absence if that tool is missing. Other source text delegates to the named plugin or the conversation. Images belong to the executing plugin. An explicit loopback root URL instead opts into this plugin calling ComfyUI directly: traditional checkpoint, 512×512 workflow, 30 seconds total, maximum 8 MiB, no redirects or World tool routes. Direct images are stored under this plugin dataDir/fun/story-images (ComfyUI also saves its output); failures keep existing artwork. Text never waits. Turning the switch off sends no image requests.

Write a story is collapsed by default and remembers expansion per World in browser localStorage; editing opens and scrolls to the shared editor. Collapsing an unsaved draft shows an Unsaved changes label. No story text or credentials are saved in browser storage. New installs include four approved built-in stories; upgrades back up story data and migrate only exact copies of promoted stories, preserving other creations, active trips and memories. The story-node limit is configurable in the top card of Story World settings; default is 16 and 0 means no node-count cap. This work does not install or publish the plugin.

## 面板加载与开发构建

0.3.0 的四个面板在 Coo 中可能同时提示 `Failed to fetch dynamically imported module`。原因是入口引用了相邻 JS，而 Coo 只托管 manifest 声明的一份 JS 和可选 CSS。0.3.1 将这些依赖内联到一个入口；已安装用户应更新到修复版本，用户地点、剧情与出游数据格式沿用 0.3.0。

前端源码位于 `webui/`，`dist/webui.js` 是发布产物。维护者修改源码后运行 `npm ci`、`npm run build:webui`；不要直接修改生成文件。`npm test` 和 `npm pack` 会先自动构建。esbuild 仅为开发依赖，安装插件无需构建工具。

验包会把实际入口作为无相邻资源的模块加载，面板交互测试也使用此入口。发布与实机验收步骤见 [PUBLISHING.md](PUBLISHING.md)。

## 面板里的出游手账

- **去哪儿**：查看当前行程，用「现在开着 / 室内 / 户外 / 夜游 / 我的地点」快捷筛选，再按名字、别名或标签搜索。分类依据地点已有标签。
- **纪念册**：切换全部行程、珍藏与心愿；行程按日期排列，点「查看详情」回看路线、完整事件、选择结果、收获与回家备注。心愿页点击「记个心愿」再填写，保存成功后收起。
- **纪念品架**：按地方查看收藏小卡，展开物品可看保留下来的行程回忆；探索进度独立显示，没有购买纪念品也能看到逛过哪些地方。
- **故事工坊**：以用户自填为主，提供简易表单和高级 JSON 编辑、校验、预览与启停管理。

四个面板跟随宿主明暗主题，支持窄屏与键盘操作。刷新失败会保留上次内容，可点击重试。旧行程详情若已超出保留窗口且没有珍藏，长期收藏账本仍会保留。

## 自己编写故事与内置故事

第四张面板「故事工坊」用于自己写剧情。选择地点（包含自填地点）和起始项目，填写小事、提问、两个选项及各自后续，点击「保存新故事包」才写入。可以选触发时段；不填时段就只按地点、项目和营业条件判断。

0.3.3 的 `BUILTIN_STORY_PACKS` 含四篇获批作品：《折潮港的第七封回信·简编版》《雨停前的小小清单》《桥底下的回声》《被换掉的说明牌》；前两篇为 v2 双人故事，后两篇为用户提供的 v1 故事，分别绑定江边和博物馆。发布包不含旧五篇正文。旧五篇与样章不再分发；作者列表默认显示这四篇内置故事，用户仍可继续编写自定义作品。作者表单默认收起，按 World 记住同一浏览器的展开状态；从列表编辑会展开并滚到共享编辑器，收起时保留草稿并提示「有未保存修改」。浏览器只记折叠布尔值，不存作品正文或密钥。没有专属剧情时仍可正常逛项目、遇到普通小事、买纪念品和拍照。

- **固定 ID 退役迁移**：旧 `stories.json` 先备份原文，再只移除 `riverside-late-lights`、`market-last-lantern`、`con-poster-hour`、`duo-cafe-date`、`creek-drift-letter`；`venues.json` 同理只移除 `user-story-creek-letter`。备份为原文件旁 `.r4-presets-*.bak` / `.presets-033-*.bak`，完成标记避免重启重复清除。备份失败不覆盖原文件并阻止后续写入。行程、回忆、用户其他作品与地点保留。
- **新增故事晋升迁移**：升级时独立备份 `stories.json`，只从作者库移除与 `bridge-echo-solo` / `swapped-plaque-riddle` 内置定义完全一致的副本；保留改写版本、原有禁用选择与用户其他作品。单独完成标记避免重复处理；失败保留备份并阻止后续写入。
- **独立保存创作**：用户剧情和启停设置保存在 `<dataDir>/fun/stories.json`，地点在 `venues.json`。除上述退役 ID 与完全匹配副本迁移外，不覆盖自填内容；重复导入须明确勾选覆盖。
- **清空记录不会清掉创作**：清空出游记录只清行程状态；自填地点、用户剧情与预设启停仍保留。移除剧情包也不会改写已经保存的经历。
- **地点可以自己加**：绑定稳定地点 ID，改显示名仍可用；关联地点或项目被删除时，包显示「暂不可用」，普通出游继续。恢复对应内容或修改剧情包后可再用。
- **高级创作可校验和预览**：展开「高级编辑」，支持模板、JSON 校验、分支预览、导入和导出。校验与预览不保存、不替她行动。同 ID 更新要明确选择覆盖；更换剧情版本不会让正在进行的一趟从头重演。

`fun_story` 与面板共用同一套操作：`list/template/validate/preview/export/import/enable/disable/remove`。最多 20 个自定义包；每包不超过 32 KB，节点上限默认 16，可在「故事工坊 → 设置」首卡片修改，填 0 表示不限节点数；选择提供 2–4 个选项。JSON 版本为 1，节点引用需存在、可到达且无循环。包只提供文本与分支，不执行脚本，不自动移动、等待或增送物品。

## 双模式：选项式故事与自由场景包

两种故事可以同时存在，共用同一趟行程、存档、回执和回忆。

- **选项式（version 1 / 2）**：作者写好节点和 2–4 个选项，玩家点选；鱼自主模式也只是从给定选项里挑。原有四篇内置故事都属于这种，行为不变。
- **自由模式（version 3「场景包」）**：作者只写大方向（premise）、正史（canon）、禁区（forbidden）、人物、地点、开场、目标与收尾条件；没有节点、没有选项，每一回合由主持即兴演。

### 三个开关（都在 `worlds.fun`）

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `funStoryTextOn` | `false` | 允许从文字通道（QQ / 控制台）开始和推进故事。关掉时 `fun_story_start` / `fun_story_act` 明确报未开启，六个只读查询照常；面板永远可玩。World 看不到消息来源，所以这是「允许文字通道」的总开关，不能只对 QQ 生效。 |
| `funStoryFree` | `false` | 允许 v3 场景包进入候选与开局。关掉时 v3 只显示「自由模式未开启」。 |
| `funStoryFreeTurns` | `40` | 自由模式单趟回合上限（1 回合 = 1 次模型调用）；场景包自己写了更小的 `maxTurns` 就按更小的来。 |

### 在聊天里怎么玩

```
fun_story_current  → 拿 tripId / stamp / startStamp
fun_story_start    { packId, revision, startStamp, confirm: true }
fun_story_act      { tripId, stamp, intent: "say", say: "用户原话" }
fun_story_act      { tripId, stamp, intent: "close", confirm: true }
```

选项式故事里，`say` 先和选项文字做精确匹配，命中就直接提交；对不上时只返回 `needConfirm` + `proposalId`，用户确认后再带 `proposalId` 和 `optionId` 调一次才提交——聊天里不存在「模型替你选」的静默路径。自由模式每条 `say` 推进一回合。`tripId` / `stamp` 过期会返回 `STALE` 和最新戳，不要猜，重新读一次。

### 自由模式守住了什么

1. **正史只读**：`canon` 每回合注入，且不进入可变状态，主持无法改写。
2. **增量白名单**：主持每回合只能返回 `{narration, delta, endRequest?, summary?}`；`delta` 只能改作者登记过的 `facts` / `flags` / `counters`，未登记、类型错、越界都整份拒绝，重试一次后仍不合法就不落盘。
3. **结局由程序判定**：主持只能请求收尾，条件不满足只记一次拒绝、这一回合照常发生；条件满足才真正结束。
4. **滚动摘要**：每 6 回合重写 ≤200 字摘要，和 `canon` 一起注入，避免越聊越偏。日志保留最近 40 条，回合上限用尽先收尾，不自动续段。

自由模式的面板是回合日志 + 输入框 + 收起；每一回合都留一个检查点，可以「退回上一回合」（状态和日志一起回滚，已经花掉的模型调用不退）。作者视图可在「选项式故事 / 自由场景包」之间切换：自由场景包有结构化表单（作品资料、大方向与正史、人物与地点、状态与收尾四组），填完即可保存、预览和隔离试玩；更细的条件仍走 JSON，另有「自由模式模板」可一键填入。

生成剧情图片时，自由模式取最后一条真实叙述加场景包里的地点描写作为场景描述，不会拿选项式行程的事件去凑；文字始终不等图片。

**群里多人时**：只有一个写者。玩家说什么都只是 `say`，由主对话把这一回合里几个人的话合并成一句再提交；程序不投票、不等待。同一 `tripId + stamp` 只允许一次提交，第二个调用会拿到 `STALE` 和最新戳。日志里的 `from` 只记录是谁说的，不授予权限；结束这一段仍要 `confirm: true`。

**谁来做这个选择**：文字通道按当前回合身份提交。用户回合时，鱼可以按用户原话（选项文字，或「第二个」这类序号）替用户提交，回执与日志记为 `owner`；含糊的话只给一个待确认提议。轮到鱼自己的回合（双人故事的 fish 回合），鱼以 `fish` 身份提交。结束这一段仍要用户明确确认。

**鱼自己游玩是持久偏好**：开关存进这一趟（`storyRun.autoplay`）。轮到你选择时它暂停，你选完鱼会自动接着走；重新打开面板或重启 Coo 也会按偏好续上，不用每次手点。授权租约仍由服务端按回合发放，切走页面只是暂停当下。

这次没有增加小镇地图。未来如增加，可将布局作为可选层：地点继续按 ID 使用，未放置的自填地点进入列表，不要求坐标，也不影响原出游。地图支持需在实现时另外验证。

## 长期探索与完整出游手账

地点卡现在配有本地原创线稿插画，按「当前或未完行程 → 当前推荐 → 全部地点」阅读；管理说明默认折叠，地点编辑仍可从详情进入。纪念品配装饰性物件图标，插画与图标都不是实际照片，不会访问外部图床。

**长期探索**独立保存到访次数、逛过的项目、拍照点、小事和去过的时段，不随近期 40 趟详情裁剪。升级只从仍保存的近期与珍藏行程补建，已被旧版删除的经历无法恢复。详细行程继续按近期与珍藏规则保存。

**选择会留下后续**：江边可决定沿灯光走或去长椅听水声；夜市可选择接着去的真实摊位；海洋馆原有选择也有后续回应。需要她实际到达对应项目才出现，略过不会生成回应，不替她移动，不凭空增加纪念品，也不会提前把白天写成亮灯的夜晚。

**找回某一趟**：纪念册可按关键词（地点、同行人、项目与备注）、地点、起止日期取交集筛选。地点详情的「回看这里的行程」和纪念品的行程链接在原面板展开只读详情；已裁掉且未珍藏的详情不会生成假链接。工具端可用 `fun_view` 的 `query/place/company/from/to/id` 查询。

**沿途时间线**按实际记录的顺序展示进门、项目、事件、选择、收获与回家，选择与对应事件关联。旧数据缺失逐项时间或区域时明确显示未知，不拿进门时刻补造。极长行程保留进门与最近活动，并提示较早逐项细节已省略。跟随宿主明暗主题，支持窄屏、键盘和系统减少动态效果偏好。

## 两站出门

`fun_route` 先规划，再明确前往下一站；每个地点独立回家，同时在纪念册归为同一次出门。最多两站，可以途中换尚未去的下一站或取消后续，不会自动赶路。

`fun_route({ action: 'plan', places: ['夜市', '江边'], company: '阿岚' })`

回执会给路线 ID。随后用 `fun_route({ action: 'next', id })` 出发；第一站 `fun_home` 后再决定是否 next。改下一站用 `{ action: 'change', id, place: '公园' }`，提前结束用 `{ action: 'cancel', id }`，查看用 `{ action: 'status' }`。正在逛的行程保留，取消后续不会替她回家。

存储页清空出游记录会同时清除长期探索、联程记录、草稿、纪念册、心愿与收藏，地点和剧情配置仍独立保留。

## 中断后接着逛

同一天挂久了仍可接着逛；跨午夜但仍在时限内的行程也不会中断。跨天又超过时限时，已有项目、收获和待选事件会保留为「未逛完」。在「去哪儿」顶部可以点「继续逛」，或点「按已有记录回家」；她也可用 `fun_view` 找行程 ID，再调用 `fun_resume({ id })` 或 `fun_home({ draftId })`。先处理这趟，再开始新行程。

待选事件会显示问题和选项，`fun_view` 与被阻止的游逛回执都能重看；`fun_choice` 的 `optionId` 填 `skip` 可以略过。面板展示选项，由她自己决定。暂停到恢复之间的时间不计入逗留；按已有记录回家使用最后活动日期和时间，不把隔夜等待算成游玩。

## 为什么现在去

`fun_places` 只列当前营业时段能逛的项目；`fun_start` 保持简短。工具和地点卡共用心愿与重游理由：有记录时，提示当前开放但还没逛过的项目；心愿暂不可实现时，显示下一个合适时段（含跨夜）。这些都是查看时计算，不定时提醒，也不会替她出发。

## 同一处地方，不同时段不是一回事

有几处地方**会随一天的时间改变样子**，不只是换句话：

| 场所 | 时段 |
| --- | --- |
| 江边（开 17.5 小时） | 清早 / 白天 / 傍晚 / 夜里 |
| 公园 | 清早 / 白天 / 傍晚 / 夜里 |
| 爬山（05:30 就开） | 清晨 / 上午 / 正午 / 下午 / 傍晚 |
| 夜市（开到 01:00） | 刚开摊 / 最热闹的时候 / 快收了 |
| 咖啡店 | 早上 / 白天 / 夜里 |

进「江边」时回执会写 `进了江边（清早）`，后面跟的是**那一刻**的描写（江面压着薄雾、对岸只剩轮廓），不是通用那段。夜里再去一次是完全不同的一段。

时段影响三样东西：

- **进门描写**——清早的江边和夜里的江边是两段不同的话。
- **能逛的项目**——夜市刚开摊时有一半摊子还没摆好，快收的时候只剩最后几家；爬山清晨能上到观景台，下午只剩山顶和下山路。
- **随机小事件**——每个时段有专属的（「卷帘门拉下来的声音一直在响」只在快收时出现），并且排在最前面，抽中概率更高。

没配时段的十五处完全不受影响，还是原来那段描写。时段数据写歪了会被 `test/phases.test.mjs` 拦下：**开放时段内必须被完整覆盖、不留空档**（留空档会静默回落到通用描写——功能像没生效，但没有任何报错）。

跨夜是最容易写错的一处：夜市「快收了」是 `00:00–01:00`，如果按普通区间比较，`23:xx` 和 `00:xx` 都会判错。`phaseContains` 对 `to <= from` 按绕一圈处理，有专门的测试钉住。

面板上也能看到：卡片直接标出「此刻属于哪一段」，展开详情会列出这一处的**全部时段**并高亮当前那段。这样「换个时间来」这件事是她和主人都看得见的。

## 自己加地方、改预设

「地点册」现在是唯一的编辑器：浏览页点「添加地点」能加自己的地方；打开一处地点点「编辑地点」，
名字、别名、分类、标签、描写、场景名、开放时间、人多不多、推荐穿搭、能逛的、纪念品、拍照点、
可能碰上的小事、能吃能喝的品类，以及画风、关联、封面，全在一张表单里。

- **能逛的**至少一处才算「可玩场所」；留空就只是地图上的一个点（地点册里看得到，「去哪儿」不列）。
- 不可玩地点填上「能逛的」就变成可玩场所；清空又退回「只是地点」。
- 自己加的地点随时能删（可玩与不可玩都行，画风/关联/封面/住所一起清）；预设地点删不掉，只能「恢复预设」。
- 能吃能喝的话，填品类名（一行一样，**别写味道**）。

只填「名字」和「能逛的」就能用，其余留空也行。
`fun_places` 先按「开着 / 快关了 / 已经关了」排序；同一营业状态下，自己加的优先，再把最近去过的排后面。

带时段的预设在编辑页改的是**通用内容**：某段自己写了描写或项目时，仍优先用该段内容；没有阶段命中或该段没有覆盖该字段时，通用修改才生效。改开放时间不会自动移动这些阶段。若要完全自定义项目与描写，可以新建自己的地点。

**预设的二十处也能改**。在地点册里打开一处预设点「编辑地点」，改的是一份
**覆盖层**：预设常量一个字节都不动，只存你真改过的字段。改过的会标「改过预设」，
详情里点「恢复预设」就还原这一处；「住所与画风」页还有「恢复全部预设」。
预设**删不掉**（删了内置场所就少了二十处），但能恢复。名字不能改成另一处预设的正名
——不然按名字找会二义。分类和场景名由内置定义决定，不开放覆盖。

数据存在 `<dataDir>/fun/venues.json`，和「她逛到哪」的 `state.json` 分开：
一个是**你配了什么**，一个是**她去过哪儿**，清一个不会带走另一个。文件里有两块：
`venues`（自己加的 `user-`，以及从旧地点库迁来的 `place-`）和 `overrides`（预设覆盖层，按预设 id 索引、稀疏）。
每条地点带 `playable`；旧地点库只剩画风、关联、封面、住所与导入记录。

**合并规则**（你选的那条）：预设升级带来的新内容照常生效，你的改动优先。
比如你改过漫展的纪念品，以后预设给漫展加了新摊位，你仍然能拿到新摊位——
只存改过的字段就是为此：没碰过的字段继续跟着新版预设走，不会把你那一处锁死。

自填地点一律 `scene` 为空：你不知道素材库里有什么，硬填只会「库里没找到」。
所以回家回执会明说「`scene` 不用填」。自定义地点也不支持预设那套时段分段
（那是手写的十八段数据），一处地方先用一段描写就够了。预设的 `scene` /
`phases` / `kind` 同样不开放编辑，覆盖了也只认你表单里那几项。

## 吃喝的味道：一个手动开关

配置里新增「吃喝的味道去『鱼的每一天』拿」：

| 开关 | 吃喝的回执 |
|---|---|
| **开**（默认） | 「装了鱼的每一天就用 `feast_menu` → `feast_eat` 点一道真的，那里才有九维口感、香气和余韵」 |
| **关** | 只说「你在这儿喝了什么」，**一个字都不提味道** |

⚠️ **这不是自动检测**。World 契约不允许一个 World 去探测别的扩展装没装
（探测本身就是依赖，认证会查）。所以「鱼的每一天」装没装都要你自己拨这一项。
但两条路都**不编味道**：开着时她调不到 `feast_eat`，也会自然退回「只说喝了什么」。

## 名字、项目与事件要对得上

购买、拍照和吃喝允许用唯一可识别的简称，但记录统一使用清单正名。例如「鲸鱼」会记成「鲸鱼挂件」，收藏进度和重复判断也使用同一个名字；简称对应多个候选时，会列出来请她选完整名字，这次不记。旧记录不会被猜测合并或改写。

逛项目时先确定当前项目及本次有效的购买、拍照、吃喝，再筛选随机事件。明确属于其他项目的事件不会混进来；需要收获或前置经历的内置事件，只有对应事实存在时才出现。历史过滤后没有合适事件就只描述当前项目，不从原始池里补回旧事件。

## 去过的地方，它记得

再去一处以前去过的地方，`fun_go` 会说出：

```
（你之前来过这里 2 次，上一次是昨天。逛过同人展台（2 次）、舞台区。买过吧唧。）
还没去过：企业馆、舞台区、海报墙。
```

- **来过几次、上一次哪天**——「昨天」「前天」「5 天前」。
- **逛过哪儿**，去得多的标次数。
- **买过什么、喝过吃过什么**。
- **还没去过的那几处**——来过几次却总有没逛到的，这句比复述去过哪儿有用。
- 逛到某一处会说「这处你之前来过 2 次」；同一天再来一趟说「今天你已经来过一次了」。

**以前买过的东西不会再重复出现。** 上次在漫展买了吧唧，这次就不会再抽到「吧唧挑了半天」那条——那件事这次没发生。过滤只拦她**真做过**的事（买过/喝过/拍过的），不做模糊语义匹配，没做过的一律放过。

**第一次去一个字都不提**——没有「上次」的口气。只统计这一处，别的城市/别的日子的漫展不算这里。

### 修掉的一个 bug：纪念册活不过一天

`normalizeState` 以前跨天**整份重来**，`trips` 被一起清空。也就是说 **0.1.4 及以前**的纪念册每天清零——面板上的「纪念册」看起来有数据，第二天就没了。做这一版才发现。

现在跨天只清超过 TTL 的 `session`（没逛完的那一趟），TTL 内仍保留，`trips` 留着。跨天该清的是「今天正在逛什么」，不是「她去过哪儿」。有测试钉住。

## 结构化事件选择

部分现有事件会带出明确的选择，而不是只给一段文字。例如海洋馆遇到鲸影、水母缸或企鹅喂食时，`fun_wander` 回执会提供 `choiceId`、选项的 `optionId` 和简短结果。用 `fun_choice` 提交其中一个选项；选择前不能继续下一处，选择结果会写入当前行程，重启后也不会丢。没有选择要求的事件仍按原来的回执直接完成，旧状态也会自动兼容。

## 出游心愿

明确表达“想去某处”“想逛某项目”“想在某个时段去”或“想带回某件纪念品”时，可以用 `fun_wish` 记录；`fun_wishes` 查看全部心愿。心愿支持暂缓、恢复和取消，状态会写入插件自己的状态文件。

心愿只在真实动作发生时完成：进门完成地点心愿，逛到项目完成项目心愿，在匹配时段进门完成时段心愿，实际买到对应纪念品完成纪念品心愿。`fun_places` 和 `fun_start` 会在营业状态排序之后优先显示当前可实现的心愿及其缘由；不会定时催促，也不会把旧行程倒推成已完成。

## 长期收藏与珍藏行程

纪念册仍保留最近 40 趟详细行程；纪念品另有独立的长期账本，记录来源地点、首次获得日期和累计次数。已有安装升级时，从目前仍保留的行程补建账本；已经被旧版本裁掉的行程无法恢复，因此不会猜补。

`fun_keepsake` 用 `fun_view` 提供的行程 ID 珍藏或取消珍藏。珍藏行程独立于最近 40 趟上限，重启后仍可查看；取消珍藏只会在它不属于近期窗口时移除详细行程，不会减少收藏次数。存储页的「清空出游记录」会清除近期行程、珍藏和收藏账本。

## 纪念品架：跨趟攒下来的东西

以前纪念册是一串孤立的趟，纪念品在数据里只是几个字符串，**跨趟没有任何归集**。
所以「这枚纪念币是第一次去游乐场那天买的」这句话说不出来——而这条数据一直躺着，只是没人取。

`fun_shelf` 和「纪念品架」面板把这事做出来了：

- **每样东西**：在哪买的、**保留记录中最早是哪天**、同一处买过几次。面板点开物品，可看对应行程的同行人、逛过的项目和回家备注；`fun_shelf` 指定地方也会列出来。
- **按地方归着**，不是一锅端。
- **集齐进度**：每处三条——逛过几处项目 / 买到几件纪念品 / 拍过几个拍照点。
  快逛遍的排在前面，这是一句「再去一次把它补完」的邀请，比一个百分比有用。

行程与收藏账本分别保存：纪念册保留最近 **40 趟**详细行程；长期收藏账本独立记录物品、来源、首次获得日期与累计次数，不随纪念册裁剪消失。可用 `fun_keepsake` 按 `fun_view` 提供的行程 ID 珍藏/取消珍藏一趟；珍藏行程不受 40 趟上限影响。升级时从仍保留的旧行程补建收藏账本，不猜补更早已被裁掉的数据。

进度按**当前场所清单**精确匹配名称：新增项目需要再逛，移除的项目不再计入分母，改名按新项目算。旧纪念品和旧行程仍保留，不做模糊合并。

日期优先使用回家时存下的 `leftDay`；旧记录没有这个字段时，按插件当前时区读取 `leftAt`，不改写旧记录。旧版没存当时的时区，因此跨时区使用时无法还原当时的本地日期。

## 去过越多次，词越多

- **常见事件每处 5 → 10 条**（全场 100 → 200）。加的不是同义改写，
  是现场还会发生的别的事。
- **少见事件每处 3 条**（全场 60）。按「熟人」写的，所以**只在来过至少一趟、
  且掷骰子撞上时才出**（默认 15%）。是概率而不是「集齐解锁」——价值在于不确定，
  按顺序解锁就变成清单了。
- **常客语气**：去过 **5 趟以上**的地方，进门会多一句关系的话
  （「来过 5 次了，江边的路已经熟悉，知道接下来会走到哪儿」），和「摆事实」那句分开放。不凭空安排认得她的店员或固定订单。
  同一个次数永远同一句话，不随机。

## 它和别的 World 是怎么联动的

**不调别的 World 的工具、不读别人的状态或日程文件**（World 契约的红线）。联动借的是 `IMGGEN-联动方案.md` 那套思路，但**不绑定任何人的库**：

1. **共享文件约定（能对上就用，对不上就不提）**：二十处里有五处（游乐场 / 海洋馆 / 庙会 / 漫展 / 咖啡店）在 `imggen-library/scenes/` 里有对应场景，那几处的回家回执会说「`scene` 填「X」」。其余十五处素材库里没有，回执就明说「`scene` 不用填」——**绝不替她编一个库里没有的名字**（那会提示「库里没找到」，那一项等于白填）。
   这个 World **完全不读**那个库，`scene` 只是条目上的一个字符串。
2. **提示词各写一句指向对方**：本插件 `ENV_PROMPT.md` 里指向 `feast_life_now` / `feast_life_play` / `feast_menu` / `feast_eat` / `imggen_draw`；鱼的每一天那边靠 `lifeFreeMenu` 加一行。
3. **鱼的每一天官方预留的 `lifeFreeMenu` 配置槽**：改一个配置值（不是代码），她就进得了「自己的时间」。

```
从0开始的肥鱼大冒险 ──「出门前/逛完查 feast」──→ 鱼的每一天
鱼的每一天 ──「lifeFreeMenu 列 fun_*」──→ 从0开始的肥鱼大冒险
从0开始的肥鱼大冒险 ──「吃喝去 feast 点一道」──→ 鱼的每一天（可选）
从0开始的肥鱼大冒险 ──「有对应场景时，发图填这个名字」──→ 生图工作室（可选）
鱼的每一天 ──（0.7.1 已有）──→ 生图工作室
```

### 吃喝那件事：味道不归我们管

咖啡店、奶茶店、餐厅、夜市这四处**能吃到能喝到**，但本插件只有**品类名**（拿铁、珍珠奶茶、一桌热菜），没有九维口感、香气、余韵，也没有实吃描写——**那些全在「鱼的每一天」的菜品库里，而本插件绝不读它**。

所以 `fun_wander` 的回执是这样的：

```
喝了：珍珠奶茶。
这儿能喝：珍珠奶茶、芋泥波波、茉莉绿茶、杨枝甘露、柠檬水。
想喝点什么就自己挑（珍珠奶茶 / 芋泥波波 / 茉莉绿茶…）。
但味道别自己编：装了「鱼的每一天」就用 feast_menu 挑一道同类的、feast_eat 真喝一口，
你才能说得出九维口感、香气和余韵；没装就只说在这儿喝了什么，一句人话，别形容味道。
```

- **装了 feast**：她自己 `feast_menu` → `feast_eat`，味道从那边来。
- **没装 feast**：她只知道「我在奶茶店喝了杯珍珠奶茶」。**没有九维、没有香气余韵，也不编。** 这正是要的降级。
- 本插件**永远不会去探测 feast 装没装**（那本身就是一种依赖），所以这段话同时给两条路，让她按手头有什么走。

`tools/check-isolation.mjs` 会静态审计这件事：`src/` 下不许出现别的 World 的包名、不许碰 `imggen-library` 或 feast 的数据目录、`import` 只许 node 内置和本包内文件、吃喝数据里不许出现味道词。它在 `npm run verify` 和 `prepublishOnly` 里都会跑。

她**自己在同一回合里**把这些串起来，不是代码替她填参数。**一个别的插件都不装也照常能逛**——只是少了那几句。

## 面板

启用后在 Coo 的世界页签里有六张面板：去哪儿、纪念册、纪念品架、地点册和故事工坊。

- **去哪儿** —— 二十处地方这时候开没开、人多不多，一次看全。开着的排前面；点一张卡展开详情（能逛的项目、纪念品、拍照点、开放时段；能吃能喝的地方还会列出能点什么），详情里会明说生图该填什么 `scene`。顶部一条是**她正在逛的那一趟**：几点进的、待了多久、逛了哪几处、买了什么、拍了哪些照、吃了喝了什么。搜索按地方名、别名、标签都能筛。
- **纪念册** —— 去过的每一趟：哪天、几点到几点、逛了哪些、买了什么、生图用的 `scene` / `outfits`、回家时她那句话。顶部四个数（多少趟、逛过多少处、多少件纪念品、多少张照）和「常去的」排行。
- **纪念品架** —— 跨趟攒下来的东西按地方归着：每样第一次是哪天拿到的、同一处买过几次；下面是每处的集齐进度（逛过几处 / 纪念品几件 / 拍过几个点），快逛遍的排前面。
- **地点册** —— 唯一的编辑器：浏览、添加和修改全部地点字段（场所 + 画风 + 关联 + 封面），管理住所与默认画风，迁入小世界备份。分类下拉按「玩乐与热闹 / 自然与户外 / 文化与展馆 / 吃喝与休息 / 故事地点 / 其他地点」分组显示中文；上方快捷筛选可分「全部 / 故事地点 / 我的故事地点 / 常规地点 / 可玩场所 / 我的地点 / 住所」，并能与分类、关键词搜索叠加。故事地点按当前故事包实际绑定的地点标记。

面板的查看与自动刷新只读，不改动出游状态。地点编辑、心愿管理、珍藏和未完行程恢复须明确点击才写入。面板每分钟刷新一次营业与时段信息。

面板可处理已有的未完行程，不提供「点一下让她去这儿」——新行程的进门和游逛是**她自己**的动作，
替她按下去就等于代码替她做决定，那和这个插件的立意相反（见下面「刻意没做的」）。

## 配置（`worlds.fun`，6 项，凭据不在普通配置中）

| 键 | 默认 | 管什么 |
|---|---|---|
| `funOn` | `true` | 总开关。关掉=不注入场所清单，工具和面板照旧可用 |
| `funSessionTTLMin` | `90` | 一趟挂多久就不再算「正在逛」；**不会催她回家，也不替她记** |
| `funAskReport` | `true` | 回家回执要不要提醒她 `feast_life_play` 记一笔、跟主人说一句 |
| `funTasteFromFeast` | `true` | 吃喝的味道去不去「鱼的每一天」拿（关掉就只说吃喝、一个字不提味道）。**不是自动探测**，装没装都要自己拨 |
| `funStoryDM` | `false` | 可选文本主持；接口地址与密钥在故事面板设置，Windows DPAPI 加密 |
| `funStoryImages` | `false` | 剧情图片来源在故事面板设置；默认委派，显式本机 URL 才可选直连 |

**没有「叫醒档位」这类配置**，这个 World **不推任何事件**。她什么时候出门，由「鱼的每一天」的 `lifeFreeSlots` 叫醒时那一行 `lifeFreeMenu` 顺手一提，或者她自己 `fun_start`——两套叫醒会互相抢时间轴，那是方案 B 的事。

```powershell
# D 补库：scenes/ 加「游乐场」「漫展」，神社补「庙会/夏日祭/夏夜祭」
node tools/apply-library.mjs --root "E:\Coopanion\data\home\companion\data\imggen-library"
node tools/apply-library.mjs --root "…" --write

# 鱼的每一天：lifeFreeMenu 补一行 fun_*（改配置值，不是改代码）
node tools/patch-lifeFreeMenu.mjs --config "E:\Coopanion\data\home\companion\config.json"
node tools/patch-lifeFreeMenu.mjs --config "…" --write
```

`apply-library.mjs` 里 `水族馆` 那条会报「别名齐了，跳过」——它的别名里**本来就有**「海洋馆」，定稿文档里那句「补别名」落地时发现已经补过了。

## 降级

库挪走了、鱼的每一天没装、生图工作室没装、甚至 `funOn` 关着：

- **逛照常**：二十处场所库是内置的，`fun_go` / `fun_wander` / `fun_home` 全都不依赖外部文件；
- **日程照常、生图照常**：回家回执里那两句话只是提醒，她不做也没人管；素材库里没有的场所连 `scene` 都不会提；
- **绝不报错、绝不卸载任何 World**：`envPromptVars()` 全程 try/catch，工具内部异常兜成 `failed: true`。

## 卸载

删掉 `data\extensions\node_modules\cortico-world-fun`（链接）和 `data\extensions\vendor\cortico-world-fun`（真身），
把安装时生成的 `package.json.bak-*` / `config.json.bak-*` 改名回去；或手动从两份 JSON 里删掉 `fun`。
`lifeFreeMenu` 里那一行手动删掉即可（不删也只是指向一堆不存在的工具，她会自己跳过）。
