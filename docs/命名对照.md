# 命名对照表（面板 id / 函数 / 工具前缀）

体检（2026-11-23）发现三处「名字与直觉不一致」。**改名的代价大于收益**：
面板 id 与工具名已经进了宿主契约、`describe.json`、已发布版本和用户的已有数据，
所以这份文档只做对照，不动任何 id。以后要改，先开一个带迁移的版本。

## 1. 面板 id

| 宿主里的 id | 页签名 | 管什么 | 容易误会成 |
|---|---|---|---|
| `home` | 家 | 房间、十个活动、热点、快照、画架 | — |
| `places` | **去哪儿** | **看**今天能去哪、此刻推荐、地点详情 | 「地点册」 |
| `locations` | **地点册** | **改**地点（全部字段、画风、关联、封面、住所）、自建地点 | 「去哪儿」 |
| `story` | 出游 | 从鱼的家出发玩故事、行程、回忆、故事设置 | 故事工坊 |
| `book` | 纪念册 | 每一趟的票笺、珍藏、心愿 | — |
| `shelf` | 纪念品架 | 长期收藏与探索进度 | — |
| `stories` | 故事工坊 | 作品库、写故事、导入、启停 | 出游 |

记忆法：**places = 看地方，locations = 管地点**；`story` 是「在路上」，`stories` 是「写故事」。
服务端 `webUi()` 的页签顺序是 `home → places → locations → story → book → shelf → stories`。

## 2. 同名函数

| 名字 | 在哪 | 实际是什么 |
|---|---|---|
| `mountPlaces` | `webui/webui.js` | 挂「去哪儿」面板 |
| `mountPlaces` | `webui/places/webui.js` | 挂「地点册」面板；入口处用 `import { mountPlaces as mountLocations }` 改名 |
| `mountStories` | `webui/stories.js` | 挂「故事工坊」 |
| `mountFishStory` | `webui/story-mount.js` | 挂「出游」 |

`mountPlaces2` 是 0.4.x 的过渡名，0.7.x 已不存在。

## 3. 工具前缀

| 前缀 | 成员 | 语义 |
|---|---|---|
| `fun_home` | `fun_home` | **回家**（写）：结束行程、出摘要 |
| `fun_home_*` | `fun_home_state`（只读）、`fun_home_activity`（写） | **房间**：看状态、换姿势。和「回家」不是一件事 |
| `fun_story` | `fun_story` | **作者工具**：模板、校验、预览、导入导出、启停 |
| `fun_story_*` | 六个只读查询 + `fun_story_start` / `fun_story_act` | **文字通道**：查公开资料、在聊天里开局与推进 |

工具描述里已写明「作者」与「文字通道」的区别；看名字分不清时以 `summary` 为准。

**哪些默认挂出来**：文字通道默认开，六个查询与 `start/act` 默认都在；`fun_story` 随 `funStoryAuthorInChat`（默认关）。把文字通道关掉则只留 `candidates` / `detail`。面板不走工具，任何时候都能写。

## 4. 评估过、决定不合并的工具

| 候选 | 结论 | 原因 |
|---|---|---|
| `fun_wishes` + `fun_wish` → `fun_wish(action:)` | **不做** | 省约 270 字符 schema，但参数从「无参查询」变成带 action 的分支，模型更容易填错；读工具保持零参数更稳 |
| `fun_places` + `fun_story_places` → 加 `scope` | **不做** | 两者契约不同：前者是中文自然语言回执，后者是给面板/文字通道的 JSON、只读、带 `startStamp`；合并会把两套返回形状塞进一个工具 |
| 面板 id `places` / `locations` 互换 | **不做** | 已发布，改名要同时迁移宿主配置、面板标题与用户习惯；只在这里加对照 |

结论一句话：**命名保持原样，文档负责解释；工具面只做「按开关暴露」和「只读记忆化」，不动契约。**
