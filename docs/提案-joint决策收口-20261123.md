## 1. 为什么做（背景事实，均已核实）

0.7.6 修掉了一个 bug：异票时服务端「只保留后投的那一票」，把对方那一票静默删了，导致两人互相清票、永远凑不出一致，面板卡在「现在轮到你 / 轮到鱼」。

修复（提交 `41041dc`）之后的行为是：

| 情形 | 现在 | 代码位置 |
|---|---|---|
| 没有人投 | 只能 `owner` 投 | `src/world.js:973` |
| 只缺一席 | 只有缺的那一席能投，另一席投会被拒 | 同上 |
| 两票一致 | 前进 | `src/world.js` 同函数末尾 |
| 两票不一致（`require-agreement`） | **不前进、两票都留**，谁都能改自己那一票 | `src/world.js:997` |
| 两票不一致（`owner-final` / `fish-final`） | 按指定那一席的票前进 | 同函数 |
| 异票时回家 | 可用 | `src/world.js:2231`（`close` 与 `step` 无关） |

**但结构问题还在**：「当前轮到谁」这条规则现在有三份实现，靠三处手工保持一致：

1. `src/world.js:2302` `#textVoter(pending)` —— 聊天通道用
2. `src/story-panel.js:135-139` `currentActor` —— 生成给面板的 payload
3. `webui/story/panel.js:478 / 513 / 518 / 541 / 594` —— 面板按 `current.actor` 做显示与禁用

这次 bug 就是第 1、2、3 份本来是同一个假设，服务端那支逻辑自己长歪了。**只要还是三份，下一次改动还会漂。**

另外一个已确认的 UX 陷阱：共同决定刚出现、还没有任何票时，聊天通道默认把这一票记成 `owner`（`src/world.js:2327-2328`）。所以如果**鱼先开口**，她那句话会被记成主人的票，随后她自己再投会被「这一步等你（主人）自己投，鱼不能代投」挡住。

## 3. 工作项 A：写规格文档

新建 `docs/JOINT-DECISION-SPEC.md`，至少包含：

1. **状态形状**：`outing.pendingChoice` 里与共同决定相关的字段（`actor: 'joint'`、`jointResolution`、`votes: { owner?, fish? }`、`options`、`id`），并注明 `src/state.js:269-273` 的归一化只接受合法选项 id、非法值丢弃。
2. **迁移表**：一行一个动作 → 前置条件 → 结果（`waiting` / `disagree` / `advance` / `reject`）→ 票面变化 → 给用户的文案要点。
3. **谁能做什么**：**任一席随时可以投、也可以改自己那一票**（只写自己那一席，永不代投）；`skip` 在 joint 里永远非法。**没有先后限制**——这是 2026-11-23 拍板的（§6）。
4. **三种 resolution**：`require-agreement`（默认，必须一致）、`owner-final`、`fish-final`，各自「不一致时」怎么算。
5. **明确不做**：不做超时判定、不把等待当同意、不替任何一席代投（`substitute` 不适用于 joint）、异票不写 `choices` 记录（只留票面）。
6. **已拍板的决定**（§6），写进规格当规则，不要再标成「待定」。

写法参考同项目的 `README.md` 的表格风格；feast 的 `TOGETHER-SPEC.md` 是这种「先定状态和迁移表再写码」的范例，但**不要去访问那个仓库**（网络现在不稳），照本提案写即可。

| 维度 | 取值 |
|---|---|
| resolution | `require-agreement` / `owner-final` / `fish-final` |
| 先投顺序 | 主人先 / **鱼先**（拍板后新增，必须覆盖） |
| 第二票 | 与第一票相同 / 不同 |
| 附加动作 | 无 / 任一方改票 / `skip` / 非法 optionId / 同一席连投两次 / 中途 `close` |

断言四件事，每个用例都断言：

1. 动作后 `pending.votes` 的精确内容；
2. `pending` 是否存在（前进 = 被清空）；
3. `trip.actor` 与 `trip.joint.stage`；
4. 被拒时：`ok === false`、**且票面与 `stamp` 完全没变**（拒绝必须是纯拒绝，不能有副作用）。

再补三条（第二、三条是防止多份实现再漂的关键）：

- **鱼先投被记在鱼名下**：空票面时 `fun_story_act({ say, as: 'fish' })` 之后，`votes` 必须是 `{ fish: X }`，`trip.actor` 是 `owner`；**不能**变成 `{ owner: X }`。
- **同一状态、三个入口一个答案**：对每种 `votes` 组合，`fun_story_current` 的 `trip.actor`、面板 `status` 的 `trip.actor`、`fun_story_act` 的 `as` 判定，必须相等。
- **面板文案与服务端阶段一致**：`trip.joint.stage === 'disagree'` 时面板提示必须含「不一样」类字样；`waiting-fish` 时含「鱼」。

## 6. 已拍板（2026-11-23，用户确认，照此执行）

### 6.1 鱼可以先投 —— **已同意，属行为变更**

- **拍板**：任一席都可以先投。规则收敛成一句：**每席随时可以投、也可以改自己那一票，只写自己那一席；两票都在且一致才前进。** 不再有「缺哪一席就只许那席投」的限制。
- **要改的地方**：删 `src/world.js:973` 的 `missing` 逻辑；`#textVoter` 空票面默认 `owner` 但接受 `as: 'fish'`；对应三条文案。
- **为什么**：故事提示词写的是「两席各选一项」，没规定先后；现状下鱼先开口，她那句话会被记成主人的票，是明确的错误归属。
- **连带更新**（别漏）：
  - `CHANGELOG.md`：新增一段，写明「任一席可先投；每席随时可改自己那一票」，并注明这是行为变更。
  - `用户手册.md` §12 与 `README.md` 里讲共同决定的句子，补一句「谁先投都行，也可以随时改自己那一票」。
  - `src/story-examples.js` 里内置故事包的 prompt 文案不必改（它没规定先后），但**确认**它没写「你先选」这类字样；写了就一起改。

### 6.2 异票不写 `choices` —— **已同意，保持现状**

票面本身就是记录，不额外推一条「双方意见不同」。测试里不要断言 `choices` 里有异票条目。
