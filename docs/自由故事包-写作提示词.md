# 自由故事包（v3）写作提示词

给要写「自由模式」故事包的群友。**用法两步**：

1. 把下面「复制给 AI 的提示词」整段发给你常用的 AI，把【】里的 4 个信息填好；
2. 把 AI 返回的那段 JSON 存成 `.json`（UTF-8），在「故事工坊 → ＋ 编写故事 → 从文件导入」导入，回「出游」就能出发。

> 先确认：配置页「世界 → 设置 → 从0开始的肥鱼大冒险 → **自由模式（场景包）**」已经打开（默认是关的）。不打开，自由包在作品卡上会显示不可出发。

---

## 0. 自由模式和选项式有什么不一样

| | 选项式（v1 / v2） | 自由场景包（v3） |
|---|---|---|
| 作者写什么 | 节点、事件、选项、每个选项的后续 | **只写设定、状态和收尾条件**，不写分支 |
| 玩起来 | 一步一选 | 每一回合玩家**说一句**，主持（模型）按设定即兴演 |
| 长度 | 节点数决定 | `metadata.maxTurns` 决定每段回合数；一趟最多三段，要手动点「再来一段」 |
| 收尾 | 走到结局节点 | 条件满足时，主持**请求**收尾，程序判定通过才结束 |

所以自由包的 JSON 里**没有** `nodes`、没有 `start`、没有 `choices`。写了会被导入校验拒绝（`unsupported field`）。

---

## 1. 先准备 4 个信息

| 信息 | 怎么填 |
|---|---|
| `placeId` | 这篇故事绑在哪。从「地点册」里看地点 ID（内置 20 个见文末附录）；自建地点的 ID 形如 `user-xxxxx`，**只在你自己机器上有效**，分享给群友时请改用内置地点 |
| 参与方式 | `solo`（绝大多数）、`duo`、`group`。自由模式不涉及「共同决定」，那套规则只用于 v2 节点 |
| 题材与基调 | 一句话，例如「雨夜港口的悬疑，克制、不吓人」 |
| 每段回合数 | 1–200，建议 12–40；写进 `metadata.maxTurns`，不写就用配置页的默认 40 |

---

## 2. 复制给 AI 的提示词

把下面整块复制走，把【】填掉，再发给 AI。

````text
你是「从0开始的肥鱼大冒险」的自由故事包作者。请按我给的信息，写一篇可以直接导入的 v3 自由场景包 JSON。

【已确认的信息】
- placeId：【填入地点 ID，例如 cafe】
- 参与方式：【solo / duo / group，通常 solo】
- 题材与基调：【一句话】
- 每段回合数 maxTurns：【12–40 之间的整数】

硬性要求（违反一条就会被导入校验拒绝）：
1. 只输出一个 JSON 对象本身：不要 Markdown 代码围栏，不要解释，不要在 JSON 前后加任何字。
2. 顶层只允许这些键：version、id、title、description、placeId、metadata、setting。version 必须等于 3。不要写 nodes、start、choices。
3. 所有 id（包 id，以及 cast、locations、flags、counters、facts、goals、ends 里每条的 id）只能用小写字母、数字、下划线、连字符，长度 1–24，例如 old-keeper、trust。不能有中文或大写。
4. 所有文字里不能出现网址、HTML 尖括号、文件路径，也不能出现 eval(、fetch( 这类内容。全部写成普通中文叙述。
5. 长度按字符算（中文一个字算一个）：
   title ≤80，description ≤240；
   setting.premise ≤240，setting.opening ≤400；
   setting.canon 3–12 条、每条 ≤120；
   setting.forbidden ≤8 条、每条 ≤120；
   setting.beats ≤6 条、每条 ≤60；
   cast、locations 各 ≤8 条；flags、facts 各 ≤12 条；counters ≤8 条；goals ≤4 条；ends 1–4 条。
6. setting 里的 cast、locations、flags、counters、facts、goals 必须是数组（可以是空数组 []），ends 至少 1 条。
7. flags、counters、facts 三处的 id 合起来不能重名。
8. counter 每条要写 min、max、initial，满足 0 ≤ min < max ≤ 100，且 initial 在 min..max 之间。
9. 条件 when（goals 和 ends 都用它）只能这样写：
   - 只能出现 all / any / flag / counter / fact 中的一个键；
   - all、any 里放 1–8 个子条件，可以嵌套；
   - flag：写一个已经声明过的 flag id；
   - counter：写一个已经声明过的 counter id，并且至少给 gte 或 lte 一个整数；
   - fact：写一个已经声明过的 fact id，并给 equals（字符串）。
   例：{"all":[{"flag":"asked-name"},{"counter":"patience","gte":3}]}
10. ends 每一条都必须有 when（没写会被导入校验拒绝）；goals 也请一定写 when，不写会被当成「一开始就达成」。

内容要求：
- 简体中文，语气具体、克制，不写网络梗，不替玩家决定他没说过的事。
- premise：一两句说清「这是哪、眼下要解决什么」。
- canon：3 条以上不可动摇的事实（时间、地点、人物关系、已经发生的事）。每回合都会给主持看，绝不能和故事冲突。
- forbidden：明确不许发生的事（谁不会出现、不能用什么力量、不能提前揭晓什么）。
- cast：1–3 个主要人物，给 name、role；可选 secret（只给主持看，别写成玩家已经知道的）。
- locations：1–3 个场景，给 name 和一句 desc。
- opening：玩家进入故事时看到的第一段（≤400 字），只写已经发生的画面，不替玩家做决定。
- flags / counters / facts：只登记真的会变的状态，宁少勿多。fact 的 initial 是一句短文字。
- goals：玩家可以达成的 1–2 个目标，用 when 判定。
- ends：1–2 个收尾，用 when 判定；不要写「时间到了自动结束」。
- beats：2–4 条氛围提示，每回合轮换给主持用。

输出模板（把尖括号里的内容换成你自己的，不要保留尖括号）：
{
  "version": 3,
  "id": "<英文小写 id>",
  "title": "<故事标题>",
  "description": "<不剧透的一句话>",
  "placeId": "<地点 id>",
  "metadata": {
    "mode": "free",
    "author": "<你的名字>",
    "release": "1.0.0",
    "genre": "<题材>",
    "synopsis": "<不剧透的简介，≤240 字>",
    "participation": "solo",
    "maxTurns": <12–40>
  },
  "setting": {
    "premise": "<一两句前提>",
    "canon": ["<不可动摇的事实 1>", "<事实 2>", "<事实 3>"],
    "forbidden": ["<不许发生的事>"],
    "cast": [{ "id": "<人物 id>", "name": "<名字>", "role": "<身份>", "secret": "<只有主持知道的秘密>" }],
    "locations": [{ "id": "<场景 id>", "name": "<场景名>", "desc": "<一句描述>" }],
    "opening": "<开场画面，≤400 字>",
    "flags": [{ "id": "<flag id>", "label": "<给人看的名字>", "initial": false }],
    "counters": [{ "id": "<counter id>", "label": "<给人看的名字>", "initial": 0, "min": 0, "max": 5 }],
    "facts": [{ "id": "<fact id>", "label": "<给人看的名字>", "initial": "<初始值>" }],
    "goals": [{ "id": "<goal id>", "text": "<目标文案>", "when": { "all": [{ "flag": "<flag id>" }] } }],
    "ends": [{ "id": "<end id>", "text": "<收尾文案>", "when": { "all": [{ "counter": "<counter id>", "gte": 3 }] } }],
    "beats": ["<氛围提示 1>", "<氛围提示 2>"]
  }
}

输出前自己检查一遍：
- 顶层是不是只有 version、id、title、description、placeId、metadata、setting 这 7 个键？
- 有没有把 id 写成中文或大写？有没有重复 id？
- when 里引用的 flag / counter / fact 是否都在 setting 里声明过？counter 条件是否给了 gte 或 lte？
- ends 是否至少 1 条、每条都有 when？
- 有没有网址、尖括号、路径？
- JSON 能不能被 JSON.parse 解析？是否 ≤32 KB？

只输出 JSON。
````

## 3. 字段速查表

### 3.1 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | ✅ | 必须是 `3` |
| `id` | ✅ | 故事包 ID，`[a-z0-9_-]{1,24}`，同一台机器上唯一 |
| `title` | ✅ | ≤80 字 |
| `description` | — | ≤240 字，作品卡上的一句话 |
| `placeId` | ✅ | 绑定的地点 ID，`[a-z0-9_-]{1,40}`，必须是真实存在的地点 |
| `metadata` | ✅ | 见下表 |
| `setting` | ✅ | 见下表 |

### 3.2 metadata

| 字段 | 必填 | 说明 |
|---|---|---|
| `mode` | ✅ | 必须是 `"free"` |
| `author` | ✅ | ≤80 字 |
| `release` | ✅ | 版本标签，`[A-Za-z0-9][A-Za-z0-9.+_-]{0,23}`，例如 `1.0.0` |
| `genre` | — | ≤40 字 |
| `synopsis` | ✅ | ≤240 字，不剧透 |
| `participation` | ✅ | `solo` / `duo` / `group` |
| `durationMinutes` | — | 1–600 的整数 |
| `maxTurns` | — | 每段回合数，1–200 的整数；不写用配置页默认值 |

### 3.3 setting

| 字段 | 必填 | 上限 | 说明 |
|---|---|---|---|
| `premise` | ✅ | 240 字 | 前提 |
| `opening` | ✅ | 400 字 | 开场画面 |
| `canon` | ✅ | 3–12 条，每条 120 字 | 不可动摇的事实 |
| `forbidden` | — | 8 条，每条 120 字 | 禁区 |
| `cast` | ✅（可为 `[]`） | 8 条 | `{id, name≤40, role≤120?, secret≤120?}` |
| `locations` | ✅（可为 `[]`） | 8 条 | `{id, name≤40, desc≤160?}` |
| `flags` | ✅（可为 `[]`） | 12 条 | `{id, label≤40?, initial?: true}` |
| `counters` | ✅（可为 `[]`） | 8 条 | `{id, label≤40?, initial, min, max}`，`0≤min<max≤100` |
| `facts` | ✅（可为 `[]`） | 12 条 | `{id, label≤40?, initial≤200?}` |
| `goals` | ✅（可为 `[]`） | 4 条 | `{id, text≤120, when?}`；**不写 when 会被当成一开始就达成** |
| `ends` | ✅ | 1–4 条 | `{id, text≤120, when}`，`when` 必填 |
| `beats` | — | 6 条，每条 60 字 | 每回合轮换的氛围提示 |

### 3.4 when 的四种写法

```json
{"flag": "asked-name"}
{"counter": "patience", "gte": 3}
{"counter": "patience", "lte": 1}
{"fact": "cup", "equals": "空的"}
{"all": [{"flag": "asked-name"}, {"counter": "patience", "gte": 1}]}
{"any": [{"flag": "met-keeper"}, {"counter": "trust", "gte": 4}]}
```

- 一个 when 里**只能有一个**主键（`all` / `any` / `flag` / `counter` / `fact`）；
- `all`、`any` 里可以继续嵌套，1–8 个；
- flag / counter / fact 的 id 必须先在上面对应数组里声明。

## 5. 导入、出发、玩

1. **导入**：故事工坊 →「＋ 编写故事」→ 起点「从文件导入」→ 选 `.json`（单个 ≤32 KB）。
   也可以把 JSON 粘到「完整 JSON → 故事包 JSON」→「校验 JSON」→「导入故事包」。同 ID 已存在要勾「覆盖同 ID 故事包」。
2. **出发**：作品卡上点「现在出发」。
3. **玩**：每一回合在输入框说一句你想做什么，点「说这一句」。没有选项，主持即兴演。
   - 每段到 `maxTurns` 会停，想继续点「**再来一段**」（一趟最多三段，要你手点）；
   - 满足 `ends` 条件时故事会收尾；随时可以「**先回家**」按已发生的片段结束；
   - 等待、切页面都不会推进，也不会替你说任何话。
4. 想改：回到故事工坊编辑，或重新导入同 ID 覆盖；已经在玩的行程不会自动改内容。

## 6. 常见报错 → 怎么改

| 校验器说 | 实际原因 | 怎么改 |
|---|---|---|
| `root: invalid JSON` | AI 输出带了 Markdown 代码围栏、解释或多余文字 | 只保留 `{` 到 `}`，用 JSON 校验器过一遍 |
| `root: JSON exceeds 32 KB` | 文本太长 | 删减 beats / canon / synopsis，或把故事拆两篇 |
| `$.nodes: unsupported field`（或 `$.start`） | 把 v1/v2 的结构带进来了 | v3 不要 `nodes`、`start`、`choices` |
| `metadata.mode: must equal free` | 少了 `"mode": "free"` | 补上 |
| `metadata.participation: must be solo, duo, or group` | 写成了「单人」之类 | 用英文枚举值 |
| `id: must match [a-z0-9_-]{1,24}` | id 有中文、大写、空格、连字符以外的符号，或超 24 字符 | 换成小写英文/数字/`-`/`_` |
| `setting.canon: needs at least 3 fixed facts` | canon 少于 3 条 | 补到 3 条以上 |
| `setting.ends: needs at least one ending` | ends 是空数组 | 至少写 1 条，且带 when |
| `...when: must contain exactly one of all, any, flag, counter, fact` | when 里写了两个主键，或写了别的键 | 一个 when 只留一个主键 |
| `...flag: unknown flag id` / `counter: unknown counter id` / `fact: unknown fact id` | 条件引用了没声明的状态 | 先在 flags / counters / facts 里声明 |
| `...: counter condition needs gte or lte` | counter 条件没给阈值 | 补 `gte` 或 `lte` |
| `setting: flag/counter/fact ids must not repeat across sections` | 三处用了同一个 id | 改掉其中一个 |
| `setting.cast: must be an array of at most 8 entries` | 写成了对象，或超 8 条 | 用数组，删到 8 条以内 |
| `...: exceeds N characters` | 某个字段超长 | 按第 3 节的上限删减 |
| `...: executable or network/path content is not allowed` | 文字里有网址、`<`、`>`、路径、`fetch(` 之类 | 改写成普通叙述 |
| `metadata.release: must be a short version label` | 版本标签不合规 | 用 `1.0.0` 这种 |

## 8. 写完之后

- 自己先玩一遍：第一回合说一句，看主持有没有跑出 canon / forbidden；跑偏就把它写进 `forbidden` 或补一条 `canon`。
- 分享只发 `.json` 这个文件；群友导入时如果提示同 ID，勾「覆盖同 ID 故事包」或让对方改一个 id。
- 想给故事配封面：那是「地点册 → 本地插画」的事，不在故事包里写图片路径（会被判为非法路径内容）。
