## 0. 一句话

页签变成 **家 / 出去玩 / 纪念册 / 纪念品架** 四个：把 `places`（去哪儿）、`locations`（地点册）、`stories`（故事工坊）三个面板的**方法与界面**并进 `story`（出去玩），面板 id 本身不重命名，改为在 `story` 上以 `admin:*` / `library:*` 前缀转发；`home` / `book` / `shelf` 原样不动。**没有任何数据迁移**。

## 1. 为什么要改

群友（八云枫）的原话：UI 比同类游戏还难用，想法太多；建议就两大类，「出去玩（故事模式）」「附近逛（家、游乐园啥的）」。

对着代码看，问题不是「东西太多」，是**同一件事被切成了三段导航**：

| 用户想做的一件事 | 现在要先去哪 |
|---|---|
| 挑个地方开一趟 | 去哪儿 |
| 正在玩、读剧情、看进度 | 出游 |
| 写故事、导入别人写的包 | 故事工坊 |
| 改地点名字、加个新地方 | 地点册 |

四件事其实是「出去玩」的四个阶段，却各占一个页签；而真正的两个大分类（故事 / 附近逛）在界面上根本看不见。0.7.7 又给对话式出游加了可滚动选项区，页签还是 7 个。

## 2. 目标形态

页签（4）：**家 · 出去玩 · 纪念册 · 纪念品架**

`出去玩` 页内的层级（从上到下就是使用频率）：

| 位置 | 内容 | 数据来源（现有面板） |
|---|---|---|
| 顶部 | 正在这一趟：地点 · 第几站 · 进度条 · 继续 / 收尾 | `story.status` |
| 二段 | 两个入口：`出去玩 · 故事模式` / `附近逛逛` | `places.list` + `story.catalog` |
| 三段 | 今天适合去（推荐主卡）+ 身边的卡 | `places.list` |
| 四段 | 这一处的图（她画好了 / 她还没画） | `story.status.images` + `storyImageRead` |
| 五段 | 写故事 / 作品库 | `stories.*`（原样搬） |
| 六段 | 这一趟走过的地方 → 纪念册 | `story.status.memories` |
| 页脚 | 管理地点 · 故事设置 · 高级（齿轮） | `locations.*` + `story.storySettings` |

**关键取舍：有行程时不做门户页。** 一旦有正在进行的行程，「出去玩」直接就是对话式剧情（现在的 `story` 面板），四个入口收进顶部一条。门户（两个大按钮 + 推荐 + 写故事）只在**没有行程**时出现——这既是群友要的「简单」，也不会让玩家玩到一半还要先过一道门。

## 3. 宿主契约：这次查证到的事实

改动全被这几条卡着，先记下来（文件都在本机 Coo 里，只读）：

| 事实 | 依据 |
|---|---|
| 面板声明只有 `id / title / description / getMethods` 四个字段，**没有 hidden、没有 order** | `resources\app\build\cortico\src\core\types.ts` 的 `WorldPanelDecl` |
| 所以 **页签数 = 声明数**，想少一个页签只能少一条声明 | 同上 |
| 面板调用走 `POST /api/webui/providers/world%3Afun/panels/:panel/:method`，body `{args}` | `build\cortico\src\web\server.ts` |
| `GET` 只放行声明里 `getMethods` 列出的方法；`POST` 走同源闸门后放行任意方法 | `build\cortico\src\web\webui-pages.ts` |
| 面板必须先被声明，否则 `no-panel` → 404 | 同上 `resolvePanel` |
| 客户端导出的 mount 必须与服务端声明一一对应 | `test\panels.test.mjs:268-272` |
| 页签顺序被逐字断言 `home, places, locations, story, book, shelf, stories` | `test\panels.test.mjs:294` |

第四条带来一个**反直觉的结论**：删掉 `locations` 声明之后，它的 `/panels/locations/*` 端点会一起消失，所以「把地点册嵌进出游」不能靠跨面板调用——必须把方法挂到 `story` 面板上。这就是下面方案要前缀的原因。

## 4. 三条路线

| 路线 | 页签 | 改声明 | 工作量 | 风险 | 结论 |
|---|---|---|---|---|---|
| **A（推荐）** | 4 | 删 `places` / `locations` / `stories`，方法并入 `story` | 约 2.5–3 天 | 宿主对「旧面板 id 消失」的处理未知，要探针 | 达成群友要的两大类 |

## 5. 方案 A 的技术形态

### 5.1 服务端：`story` 面板成为方法超集

`src/world.js:1913-1940` 的 `panels` 数组改成四条：

```js
panels: [
  { id: 'home', ... },                      // 不动
  { id: 'story', title: '出去玩', getMethods: [...], methods: [...], ... },
  { id: 'book', ... },                      // 不动
  { id: 'shelf', ... },                     // 不动
]
```

`story` 的 `getMethods` / `methods` = 自身方法 **∪** `admin:*`（原 `locations`：1 个只读 + 14 个写）**∪** `library:*`（原 `stories`：6 个只读 + 4 个写）。合计 **16 个只读、37 个写**方法名，集中在一条声明里（`places` 若也并进来，再加 3 只读 + 6 写）。

`#invoke`（`src/world.js:3194`）加一层分流，**前缀剥离后原样转给现有实现**：

```js
async #invoke(panel, method, args) {
  if (panel === 'story' && method.startsWith('admin:'))   return this.#invokeLocations(method.slice(6), payload);
  if (panel === 'story' && method.startsWith('library:')) return this.#invokeStory(method.slice(8), payload);  // 走作者分支
  ...
}
```

`#invokeLocations` / `#invokeStory` 里原有的 `panel === 'locations'` 分支保留（B 路线和回滚都用得上），只是多一条入口；`invoke` 里的 `throw new Error('不认识的面板')` 不动。

这个模式在 0.7.x 里已经有先例：`src/world.js:3202-3203` 就是 `story` 面板把 `locationCover` 转给 `#invokeLocations`、再用 `#storyLocations(...)` 包一层。前缀分流只是把这一条扩大成规则。

**不改任何库代码**：`#locationLibrary`、`#storyLibrary` 的调用签名不变，只是入口多了一个。

### 5.2 客户端：代理 ctx + 嵌挂

`webui/webui.js:1302-1312` 的注册表改成四条，`locations` / `stories` 两条移除，但两个 mount 函数保留，用代理 ctx 挂到 `story` 的子容器里：

```js
const proxy = (ctx, prefix) => ({
  ...ctx,
  invoke: (method, payload) => ctx.invoke(`${prefix}:${method}`, payload),
});
// 在 story 面板的二级页里：
mountLocations(proxy(subCtx, 'admin'));    // 原来叫 mountLocations 的那个
mountStories(proxy(subCtx, 'library'));    // 原 mountStories
```

两个大文件（`webui/places/webui.js` 44 KB、`webui/stories.js` 65 KB）**一行都不用改**——它们只认 `ctx.invoke`，代理在下面换掉了方法名。这是这套方案最省的地方。

`story` 面板（`webui/story/panel.js`，76 KB）只加一个外壳：没有行程时渲染门户，有行程时渲染现有对话区。**不改它内部的 DOM 契约**，`webui/story/webui.test.mjs` 的 43 条断言仍按原样跑。

### 5.3 页签标题与顺序

声明顺序即页签顺序：`home` → `story`（出去玩）→ `book` → `shelf`。
`places` 的「去哪儿」内容进 `story` 门户，`locations`、`stories` 变成二级页。
