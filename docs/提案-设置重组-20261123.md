## 4. 剧情图片：按钮 → 开关

### 4.1 语义

- **开关**：绑定 `funStoryAutoImages`（现有键，默认 `true`）。开 = 每走到新的一处 / 故事翻一页，自动把 `imggen_draw` 的 `scene/outfits/prompt` 递进她的提示词；关 = 不再自动准备。
- **总闸**：`funStoryImages` 仍在配置页。总闸关时，面板开关显示为关且禁用，旁边一句「总开关在『配置 → 从0开始的肥鱼大冒险』」。
- **手动按钮**：只有来源是 loopback ComfyUI（`validateStoryImageSource(source).kind === 'comfyui'`）时才显示「生成当前场景图片」。委派来源不显示按钮（自动就够了，按钮只重复同一件事）。
- 手动按钮不再常驻主操作位：用 `secondary/quiet` 样式，放在开关下面一行。

### 4.2 行为

现有 `#maybeAutoImageRequest` 已经做了「同一进度戳只准备一次、45 分钟过期」；开关只是把 `funStoryAutoImages` 从配置页搬到面板可见处，**服务端逻辑不用改**。开关写入路径：

- 新 RPC：`webUi().invoke('story', 'saveStoryAutoImages', [{ auto: boolean }])`。
- `#invokeStory` 增加分支 → `#saveStoryAutoImages(payload)`：
  - 更新 `this.#rawCfg.funStoryAutoImages`；
  - 调 `this.#persist?.({ funStoryAutoImages: auto })`（已有 `persist`，就是启动时补配置段用的那个）；
  - 返回 `{ ok: true, autoImages: bool }`；
  - 失败时回滚内存值并返回 `{ ok:false, error }`。
- 面板开关：`role="switch"` / `<button aria-checked>`，乐观更新 + 失败回滚 + `aria-live` 状态（照 `autoplaySwitch` 的写法，panel.js 324 行）。

### 4.3 设置页剩下什么

`settings()` 变成：

```
本机设置
  剧情图片
    [开关] 自动准备委派配图
    说明：打开后每走到新的一处/翻一页，就把 scene/outfits/prompt 递给她；画不画由她定。
    状态：图片来源（委派 / 本机 ComfyUI / 指定插件）· 总开关（开/关）
    [次要按钮] 生成当前场景图片   ← 仅直连 ComfyUI
    [折叠] 高级：自定义工作流      ← 仅直连 ComfyUI 时显示

```

`settingsIntro` 改成「这里放这一台机器的配图开关；故事长度、主持与图片来源在配置页，本地插画在地点册。」

## 5. 故事长度、主持与图片来源搬进配置

### 5.1 故事长度

- `StoryNodeLimit` 继续作为**迁移读取器**：启动时 `load()` 读旧文件，把值写进 `cfg.funStoryNodeLimit`（若配置里没有），并 `persist` 一次；之后以配置为准。
- `#storyNodeLimit.value`（`src/world.js` 462 行附近注入 `StoryLibrary` 的 `nodeLimit` 闭包）改成读 `clampInt(this.cfg?.funStoryNodeLimit, 0, MAX, 16)`；`StoryNodeLimit` 只保留「读旧文件」与校验函数，`save()` 不再被面板调用。
- 删除面板的 `buildNodeLimitSettings`（698–745）与 `saveStoryNodeLimit` RPC 的 UI 调用；RPC 可保留一版兼容（写配置），但**不再有面板入口**，也可直接删，记得同步测试（`test/story-config.test.mjs` 有节点上限用例）。
- 配置 schema：`integer`、`minimum: 0`、`maximum` 用 `Number.MAX_SAFE_INTEGER`（宿主支持 `maximum`）、`x-suffix: ' 个节点'`。0 的文案要写清「0 = 不限」。

### 5.2 主持与图片来源

| 数据 | 去处 | 迁移 |
|---|---|---|
| `apiUrl` | 配置 `funStoryDmUrl` | 启动时从 `story-secrets.json` 读出（它本来就能解密），写进配置，然后把 secrets 里的 `apiUrl` 清空 |
| `model` | 配置 `funStoryDmModel` | 同上 |
| `apiKey` | **仍留在 `story-secrets.json`（DPAPI）** | 不动 |
| 图片来源 | 配置 `funStoryImageSource` | 从 `story-images/settings.json` 读 `source` 写配置，然后 `StoryImages` 改成读配置 |
| 工作流 | 仍留 `story-images/settings.json` | 不动 |

**为什么密钥不进配置**：宿主配置页对 `string` 只渲染普通文本框（`np()` 里没有 password/secret 分支，见 §9），写进 `worlds.fun` 就是明文落进 `config.json`，比现在的 DPAPI 明显退步。所以「主持与图片来源」能搬的都搬，密钥这一项留面板，并在配置页的 `funStoryDmUrl` 描述里写「密钥在『出游 → 设置』填写，只存本机密文」。

如果用户坚持连密钥也进配置：单独开一个决定，**不要默认做**；做法是加 `funStoryDmApiKey` 字符串键 + 面板不再有密钥输入，并在 README/风险说明里写明「明文存 config.json」。见 §12。

### 5.3 迁移的执行点

在 `FunWorld#start()` 里、`#storySecrets.load()` / `#storyImages.load()` 之后、`#ensureConfigSection()` 之前后安排一次性迁移：

1. 若 `cfg.funStoryNodeLimit === undefined` 且旧文件有值 → 写入并 `persist`。
2. 若 `cfg.funStoryDmUrl === undefined` 且 secrets 有 `apiUrl` → 写配置；`model` 同理；然后 `storySecrets.save({ apiUrl: '', model: '' })` 清掉（保留 key）。
3. 若 `cfg.funStoryImageSource === undefined` 且 `story-images/settings.json` 有 `source` → 写配置；`StoryImages` 改为 `source: () => cfg.funStoryImageSource`（构造函数注入），`status()/configure()` 不再读写文件里的 `source`，只留 `workflow`。
4. 迁移每步独立 try/catch，失败只记日志，不阻止启动；迁移成功后再 `persist`，避免每次启动重复写。

## 9. 宿主配置页的能力边界（已验证）

`E:\Coopanion\resources\app\build\console\index.js` 的通用渲染器 `np()` 支持：

- `boolean` → checkbox；
- `string` → `x-options` / `enum`（select）、`x-path`（路径选择）、否则单行 text；
- `integer|number` → number + `minimum` / `maximum` / `multipleOf` / `nullable` / `x-scale`；
- 数组的 `[number, number]` 成对渲染；
- `x-hot: false` → 标「需重启」；`x-suffix` → 单位后缀。

**不支持**：textarea、password/secret、分组/折叠。所以：
- 工作流留在面板（32 KB JSON 不能塞单行输入）；
- API Key 不能放配置（没有 secret 字段，会明文）；
- 配置页会是一条长列表（20 项），文案必须短，默认值要合理。

- 本地插画：2 MB / 像素 / MIME 校验沿用；`creek-letter-ending` 不显示。

## 12. 备选与取舍（给拍板用）

1. **密钥也进配置**：加 `funStoryDmApiKey`，明文进 `story-secrets.json`？不，进 `config.json`。安全退步，**不建议**；除非用户明确要「全在一个页面」。
2. **工作流改 `x-path`**：配置键 `funStoryImageWorkflowFile` 指向 JSON 文件，`x-path` 渲染路径选择。好处是全进配置；坏处是多一个文件、路径校验、导入导出变复杂。
3. **设置页整个删掉**：把配图开关放到「出游」页顶部（沉浸条旁），`settings` 标签去掉。更干净，但改动面更大；本提案先保留标签。
4. **`funStoryImages` 与 `funStoryAutoImages` 合并**：一个 `funStoryImageMode: off|auto|manual` 枚举，配置页下拉。语义更清楚，但要迁移两个布尔、改所有判断；建议下一版再评估。
